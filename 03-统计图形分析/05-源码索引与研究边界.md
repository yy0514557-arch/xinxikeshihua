## 四、Charts 关键实现

- `src/<chart-name>/metadata.js`

- `src/<chart-name>/render.js`

## 五、程序技术栈（以 package.json 为准）

App 的 package.json 显示其主要技术包括：
- React：界面组件与状态管理。
- D3：数据可视化相关工具。
- RAWGraphs Core 与 Charts：核心图表能力和图表实现。
- Comlink：Worker 与主线程之间的调用封装。
- React Bootstrap：界面布局与控件。
- Vite：当前 package.json 的开发与构建工具。

注意：依赖版本与构建配置可能随分支更新。不要将历史技术栈描述直接当作当前版本。

## 六、研究边界与注意事项

1. 本专题以公开 GitHub 源码、README 和 Core 文档为依据，不等于逐行审计所有依赖库。
2. App、Charts、Core 是三个独立仓库，不能把某一仓库的文件缺失误判为功能不存在。
3. 32 个内置图表是当前 app 注册清单，不代表 RAWGraphs 全部可能支持的图形，也不代表统计学图表全集。
4. 图表 metadata 中的 categories 是界面筛选标签；不是严谨、互斥的学术分类。
5. 图表 metadata 的简短描述只能支持基本用途判断；更精确的统计计算、聚合、尺度与视觉选项应继续检查对应图表的 dimensions、mapping、render、visualOptions。
6. Core 的 declarative mapping 文档标注该 API 仍在定义中，不能把它描述为完全稳定的统一规范。
7. RAWGraphs README 说明输入数据在浏览器处理，不进行服务端存储；这不意味着应用没有网络请求，也不意味着用户通过 URL、SPARQL 等外部来源获取的数据不涉及网络。
8. 设计优劣、认知负担和适用场景属于进一步的可视化分析，必须与源码事实区分。
9. 本项目的目的是提炼图表分析知识，不复制整个上游源码。需要复现或运行程序时，应直接克隆上游仓库并遵守 Apache License 2.0。
