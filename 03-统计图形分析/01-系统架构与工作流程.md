# RAWGraphs｜系统架构与工作流程

## 一、三个代码层次

### 1. 应用层：rawgraphs-app

仓库：[rawgraphs-app](https://github.com/rawgraphs/rawgraphs-app)

负责网页界面与用户操作流程，主要包括：
- 数据导入：文件上传、粘贴文本、URL、SPARQL、已保存项目。
- 图表选择：展示图表名称、缩略图、描述和分类标签。
- 数据映射：把数据列拖放到图表要求的维度槽位。
- 图形定制：根据当前图表提供视觉参数。
- 预览与导出：生成图形并导出 SVG、PNG、JPG 或 .rawgraphs 项目文件。
- 自定义图表：支持从 URL、npm 或本地上传加载扩展图表。

关键源码：
- `src/App.js`：页面流程、状态管理、图表切换、项目导入导出。
- `src/charts.js`：内置图表清单。
- `src/components/DataLoader/`：数据导入。
- `src/components/ChartSelector/`：图表选择。
- `src/components/DataMapping/`：字段映射界面。
- `src/components/ChartOptions/`：视觉选项控件。
- `src/components/Exporter/`：导出。

### 2. 图表实现层：rawgraphs-charts

仓库：[rawgraphs-charts](https://github.com/rawgraphs/rawgraphs-charts)

提供具体图表模型。每一种图表通常有独立目录，常见文件包括：
- `metadata.js`：名称、描述、分类标签、缩略图、代码与教程链接。
- `dimensions.js`：图表需要哪些数据维度及其约束。
- `mapping.js`：如何把表格数据转换为图表所需结构。
- `render.js` 或图表实现文件：绘制图形。
- `visualOptions.js`：可调整的视觉参数。
- `.svg`：图标与缩略图资源。

并非每个图表目录都必须包含完全相同的文件；应以各图表实际目录为准。

### 3. 核心引擎层：rawgraphs-core

仓库：[rawgraphs-core](https://github.com/rawgraphs/rawgraphs-core)

提供跨图表复用的基础能力：
- 数据集解析与数据类型识别。
- 图表实例化与通用接口。
- 数据映射调度。
- 视觉选项配置。
- DOM 渲染与项目序列化／反序列化。

核心文档包括 workflow、chart-interface、data-parsing、declarative-mapping、rendering、import-export。

## 二、五阶段工作流

RAWGraphs Core 的 workflow 文档将创建过程概括为五步：

1. **Data loading｜数据加载**：导入表格，解析分隔符、数字格式、日期格式等。
2. **Visual model selection｜视觉模型选择**：选择要生成的图表类型。
3. **Mapping｜数据映射**：将数据列分配给图表维度。
4. **Customization｜视觉定制**：调整当前图表模型开放的视觉参数。
5. **Export｜导出**：输出 SVG、PNG、JPG 等图形文件，或保存项目数据与配置。

## 三、程序中的关键数据流

`原始文本／文件`
→ `表格数据`
→ `字段类型识别与解析`
→ `选择图表模型`
→ `字段—维度映射`
→ `mapData 数据转换`
→ `render 图形渲染`
→ `SVG／栅格图像／项目文件`

注意：图表模型不是直接读取任意表格后自动猜测所有图形含义。用户需要把数据列映射到该模型所定义的维度，程序再依照图表实现完成数据转换与绘制。

## 四、应用层状态与执行

`src/App.js` 管理当前图表、mapping、visualOptions、原始可视化实例等状态。切换图表时会清空原映射、恢复新图表的默认视觉选项，并清除旧预览。

`src/worker/worker.js` 通过 Comlink 暴露 Web Worker 方法，调用 core 的 `parseDataset` 与图表实例，执行数据解析和映射数据获取。由此可见，部分计算工作被安排在 Worker 中，以避免全部计算都直接占用界面主线程。

## 五、数据安全说明的范围

RAWGraphs README 明确说明，用户注入的数据在浏览器中处理，不进行服务端操作或存储。这是该项目 README 对其数据处理方式的说明。具体部署、外部数据源（例如 URL 或 SPARQL）和浏览器分析统计等场景仍应分别查看相应实现与隐私说明，不将这句话扩大解释为“整个网页绝不发生任何网络请求”。
