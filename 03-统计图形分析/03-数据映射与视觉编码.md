# RAWGraphs｜数据映射与视觉编码

## 一、输入数据结构

RAWGraphs Core 将输入数据定义为表格数据集：
- 每行代表一个数据记录（data point）。
- 每列代表一个数据属性（data column）。
- 第一行包含字段名，字段名应唯一。

源码文档列出的基础数据类型：
- `string`：字符串／文本。
- `number`：数值。
- `date`：日期。

应用层还提供数字与日期解析设置，例如分隔符、千位分隔符、小数分隔符、日期格式与地区设置。Core 的 `inferTypes` 用于推断字段类型，`parseDataset` 用于解析数据；文档说明推断会尝试将字段值转换为不同类型，并依据多数数据项的可转换情况判断字段类型。

## 二、Dimension｜图表维度

维度是某个图表模型所需的数据输入槽位。它不是简单的“X 轴、Y 轴”同义词。

Core 的 chart-interface 文档列出的维度定义属性包括：
- `id`：维度唯一标识。
- `name`：维度名称。
- `required`：是否必填。
- `multiple`：是否允许映射多个字段。
- `minValues`、`maxValues`：允许映射值的数量范围。
- `validTypes`：可接受的数据类型。
- `aggregation`、`aggregationDefault`：是否聚合及默认聚合方式。

维度可以直接对应视觉变量（如气泡图的 x、y、size），也可以承担分组、嵌套等更复杂的数据组织任务。

## 三、Mapping｜字段映射

Mapping 是用户数据列与图表维度之间的对应关系。用户将数据字段放入图表提供的维度槽位后，图表实现根据 mapping 确定如何取数、分组或组织数据。

典型过程：
1. 图表定义所需维度。
2. 用户选择数据列并映射到维度。
3. 图表的 `mapData(dataset, mapping, dataTypes, dimensions)` 执行转换。
4. 返回适合当前图形绘制的数据结构。
5. render 使用转换后的数据生成图形。

Core 文档还介绍 declarative mapping（声明式映射），例如使用 `get` 规则直接提取映射字段。文档同时提醒该 API 仍在定义中，使用范围与行为应以当前具体实现为准。

## 四、Aggregation｜聚合

应用常量中列出了以下聚合标签：
- Count｜计数
- Average / Mean｜平均值
- Median｜中位数
- Max｜最大值
- Min｜最小值
- Count unique｜不同值计数
- Sum｜求和
- CSV｜拼接
- CSV (unique)｜去重后拼接

是否提供聚合、默认采用哪种聚合，以及聚合作用于哪些维度，取决于图表的维度配置与映射逻辑。不能假设所有图表都支持全部聚合方式。

## 五、Visual encoding｜视觉编码

结合图表 metadata 的描述和图表接口，可以识别以下视觉通道：

| 视觉通道 | 常见变量 | 例子 |
| --- | --- | --- |
| 位置 Position | x、y、轴向位置 | 气泡图、折线图、散点结构 |
| 长度 Length | 条形长度、区间长度 | 条形图、甘特图 |
| 面积 Area | 圆面积、矩形面积、扇区面积 | 圆形填充图、矩形树图、饼图 |
| 颜色 Color | 类别或数值 | 气泡图、矩阵图、密度图 |
| 尺寸 Size | 点、圆、节点大小 | 气泡图、网络图、层级图 |
| 连接 Connection | 线、弧、弦 | 弧线图、弦图、网络图 |
| 宽度 Width | 流带宽度、连接宽度 | 桑基图、冲积图 |
| 形状／符号 Shape / Glyph | 方形、圆形等符号 | 矩阵图 |
| 方向 Direction | 流向、连接方向 | 桑基图、弧线图 |
| 分组与嵌套 Grouping / Nesting | 分类层次、父子关系 | 树状图、旭日图、矩形树图 |

此表是根据源码图表描述所做的视觉编码归纳；具体图表能否使用某一通道，应检查其 dimensions、mapping 与 render 实现。

## 六、Visual options｜视觉选项

视觉选项是图表模型暴露给用户的外观配置，Core 文档列出 number、boolean、text、colorScale 等选项类型。它们可以控制颜色、尺寸、标签、边框、画布与其他显示属性。

需要区分：
- **数据映射**决定数据如何进入图形。
- **视觉选项**决定图形如何呈现。
- 颜色比例尺虽涉及颜色视觉编码，但在 RAWGraphs 中由图表作为视觉选项提供给用户配置。

## 七、数据映射与视觉编码分析示例：Bubble chart

源码 metadata 对 Bubble chart 的说明：基础布局为散点图，用二维位置显示两个连续维度之间的关系；还可用尺寸编码一个额外数量维度，并以颜色编码数量或类别维度。

据此分析：
- 数据输入：至少两个可用于位置的连续变量。
- 位置编码：X、Y 两个维度。
- 尺寸编码：附加数量变量。
- 颜色编码：附加数量或分类变量。
- 主要任务：观察变量之间的关系，并同时比较附加变量。
- 设计风险（分析判断）：气泡面积与半径容易被混淆；大量气泡可能重叠；颜色和尺寸同时编码时需要保证图例清楚。

最后一项属于可视化设计分析，不是源码 metadata 的原文。
