# RAWGraphs｜图形分析与评价方法

## 一、分析顺序

对一个统计图形进行分析时，建议按以下顺序：

1. **分析任务**：图形要回答什么问题？是比较、趋势、分布、构成、关联、流动还是层级？
2. **数据结构**：输入数据是一张什么结构的表？每行、每列分别代表什么？
3. **字段类型**：参与映射的字段属于数值、日期还是字符串？字段类型是否与图表维度要求一致？
4. **维度配置**：图表要求哪些维度？哪些必填？是否允许多个字段？是否需要聚合？
5. **映射关系**：每个字段映射到哪个图表维度？是否进行了分组、聚合、排序或结构转换？
6. **视觉编码**：哪些数据变量被映射到位置、长度、面积、颜色、尺寸、连接、宽度、形状或方向？
7. **图形结构**：图形如何组织元素？采用坐标轴、分区、嵌套、节点—连线还是流带？
8. **交互与定制**：图表开放了哪些视觉选项？这些选项是否影响数据含义，还是只改变外观？
9. **输出与编辑**：输出 SVG 还是 PNG/JPG？是否需要在矢量软件中继续编辑？

## 二、五个核心分析维度

### A｜数据逻辑 Data Logic
- 数据记录单位是什么？
- 字段分别代表类别、数量、时间还是关系？
- 数值是原始值、汇总值、比例还是排名？
- 是否存在缺失值、重复值、异常值或数据粒度不一致？

### B｜统计图形与计算 Statistical Chart & Calculation
- 图形属于何种统计图形模型？
- 数据在绘图前是否经过计数、求和、均值、中位数、分组、排序、密度估计或层级整理？
- 图形中的长度、面积、宽度或位置是否与数值对应？
- 源码没有明确揭示的计算过程，应标为待核实，不根据图形外观猜测。

### C｜视觉编码 Visual Encoding
- 每个数据变量映射到什么视觉通道？
- 使用的是定量、定序还是定类视觉编码？
- 多个通道是否重复编码同一变量？
- 图例、单位、轴刻度与颜色尺度是否清楚？

### D｜信息架构 Information Architecture
- 信息是线性、网格、径向、树状、网络还是空间分布？
- 主要信息与次要信息如何区分？
- 是否有分组、层级、路径或时间顺序？
- 阅读顺序是否明确？

### E｜视觉叙事 Visual Narrative
- 读者首先看到什么？
- 视觉重点如何引导比较或发现？
- 图形是否支持从整体到局部的阅读？
- 标题、注释、标签与图例是否形成完整解释？

## 三、图形选择的判断逻辑

| 要回答的问题 | 可优先考察的图形 | 判断依据 |
| --- | --- | --- |
| 比较类别数值 | 条形图、多组条形图 | 类别之间的数值差异 |
| 比较构成 | 堆叠条形图、饼图、矩形树图 | 部分与整体的关系 |
| 观察时间变化 | 折线图、流图、地平线图 | 连续时间上的变化 |
| 观察分布 | 箱线图、小提琴图、蜂群图 | 中心、离散、密度或个体分布 |
| 观察变量关系 | 气泡图、矩阵图、平行坐标图 | 两个或多个变量之间的关系 |
| 观察网络流动 | 桑基图、冲积图、弦图 | 节点、连接与流量 |
| 观察层级结构 | 树状图、旭日图、矩形树图、圆形填充图 | 父子层级和嵌套关系 |
| 观察时间安排 | 甘特图、日历热力图 | 任务区间或日历周期 |

这张表是学习时的初步选择提示，不构成绝对规则。最终选择取决于数据结构、分析问题、数据量与读者需求。

## 四、图形质量检查

- 数据映射是否正确，是否把类别字段误当作数值字段？
- 数值轴是否从合理基准开始，单位与刻度是否明确？
- 面积、角度、宽度是否容易被读者误读？
- 颜色是否具有清晰、稳定的含义？
- 图形是否存在严重遮挡、重叠或标签拥挤？
- 分组、排序和层级是否符合数据逻辑？
- 是否能从图形准确读出主要结论？
- 视觉装饰是否干扰数据比较？

## 五、记录规范

每个实际案例建议保留：
- 案例名称、来源链接、获取日期。
- 原始图形图片。
- 数据来源与数据字段（如可获得）。
- 图表类型与选型理由。
- A—E 五维分析。
- 源码依据链接（若能对应到 RAWGraphs 实现）。
- 观察事实、分析推断、待核实事项分开记录。

不得只凭缩略图或图表名称推断真实数据、统计方法或作者意图。
